*P4 — folder rename / merge / delete (namespace F):*
- **F1 (LOAD-BEARING — security/correctness). A live guest share on a folder being merged-away or deleted.** A guest granted `folder_permission` on folder A: if A merges into B, A's photos now live in B (never shared); if A is deleted, photos move to Unfiled. **Recommended: BLOCK the merge/delete with 409 while any live permission points at the folder** ("revoke the share first"). Rejected alternatives: silently migrating the grant to B is a privilege escalation (B may hold private photos); silently revoking severs an active client without the owner realizing. Veto toward silent-revoke-with-a-warning if preferred.
- **F2. Delete → what happens to the folder's photos.** Recommended: **move to Unfiled (`folderId = null`)**, NOT cascade-delete photos/MinIO objects, NOT refuse-if-non-empty. Veto toward cascade-delete only if "delete folder = delete photos" is the intended semantic (then also spec MinIO cleanup + a confirm guard).
- **F3. Merge across collections.** Recommended: **require same collection** (400 otherwise) — matches the single-default-collection reality + clean `@@unique` semantics.
- **F4. Audit rename/merge/delete?** Recommended: **audit merge + delete** (new `folder_merged`/`folder_deleted` action strings — additive, no schema change) since they're destructive + interact with sharing; **do NOT audit plain rename** (cosmetic, high-frequency, matches the AP1 owner-content exclusion).

AI-generated vs custom folders.** Recommended: **allow rename/merge/delete on BOTH types** (folders are folders); accept that the worker may re-create an AI folder by its category name on the next matching upload (benign). Inline-stream vs. BullMQ job.** Recommended: **inline-stream this pass** (archiver piped to the HTTP response, on-the-fly from MinIO reads, no temp file) **with a guard cap — >500 photos (or an est-bytes threshold) → 409 "too large, narrow it down"**; async (a stored zip built by a job + a pre-signed URL when ready) DEFERRED until real usage hits the cap.
