## Investigated non-bugs (recorded per "no fabricated test results")

### [Not a bug — test-assertion artifact] Meter-fill width exact-string mismatch

- **What happened:** The first automated pass asserted the rendered `style.width` string equalled `${usedPercent*100}%` by exact match. It read back `"0.0010294%"` where the template writes `"0.0010294467210769653%"`.
- **Root cause:** browsers serialize CSS length values to ~6 significant figures when read via `el.style.width`. The two strings are the *same number*. The code (`dashboard/page.tsx` line 242) writes `width: ${pct*100}%` directly from the API's `usedPercent`.
- **Re-verified clean:** re-ran with a float-tolerance comparison — rendered `0.0010294` vs expected `0.00102944672…`, relative diff `4.5e-5`, and ≤100%. The meter genuinely reflects the API's `usedPercent`. Pass (assertion #7).

### [Not a bug — test-scope artifact] Empty-state "console errors" were login-flow 401s, not dashboard errors

- **What happened:** The first empty-state pass flagged two `401 Unauthorized` console errors.
- **Root cause:** captured with full response logging, the two 401s are `GET /api/auth/me` firing **before** the login POST completes — i.e. the pre-auth state on the `/login`/initial-load path, while the user has no session cookie yet. This is the same `authApi.me()`→redirect auth-gate pattern every page has used since Week 1-2; it is not emitted by the dashboard's own render.
- **Re-verified clean:** scoping the listener strictly to the post-login `/dashboard` render (and again on a hard reload with the cookie definitely present) yields **zero console/page errors and zero 4xx/5xx** — and the page renders correctly (`0 B of 5.0 GB used`, `0 folders · 0 collections · 0 photos total`). Pass (assertions #38–40).

## Methodology / process notes

- **Seeded via the real API + live worker, not DB fixtures** — each user signed up, uploaded fixture images whose mock-classification bucket (`sha256(bytes)[0] % 7`, read from `backend/src/lib/classification/index.ts`, not guessed) was pre-computed to land in distinct folders, then polled each photo to a terminal status. The populated user's dashboard truth (`storage`, `totals`, folder list, unfiled count) was captured from the raw `GET /api/dashboard` / `/api/collections/:id/folders` / `/api/photos/unfiled` responses and used as the assertion oracle, so the UI is checked against the actual API, not against the MR draft's numbers.
- **`usedPercent` contract confirmed at the source** — read `backend/src/routes/dashboard.ts`: `usedPercent` is a server-computed float in `[0,1]` (`Math.min(1, Number(usedBytes)/Number(limitBytes))`), so the client's `width: ${pct*100}%` and `round(pct*100)` are correct, and the server-side `Math.min(1, …)` cap is what guarantees the meter can never visually exceed 100% even if usage exceeded the limit.
- **Signup rate limit (5/15min/IP, Pending Decision 6) was hit during seeding** and handled honestly — no server restart, no fabrication. A background retry loop waited out the fixed window (~10 min) and then created all three users within one freed window (3 signups < 5 budget). Recorded here because it added real wall-clock time and is the same rate-limit friction prior reports have noted for test-account creation from a single IP; not a defect.
- **`formatBytes` was unit-tested from an exact copy of the page's function** (lines 42–51) rather than only spot-checked in the browser, so every scale (B→TB) and every degenerate input (NaN/negative/non-numeric/empty) is covered deterministically.
- **Two automated failures were run down, not dismissed** — both root-caused to the test harness (CSS float serialization; login-flow 401s swept into an over-broad error listener) and re-verified clean with corrected assertions, per "no fabricated test results."
- Test users created this session (`seedcheck_*`, `dashpop2_*`, `dashempty2_*`, `dashmid2_*`, `dashsingle_*`, `probe_*`, all timestamped `@example.com`) were not cleaned up — throwaway scratchpad accounts, no sensitive data, consistent with every prior report.
- All test scripts, generated fixtures, seeded truth (`seeded.json`/`single.json`), and raw results (`results-full.json`) live in the session scratchpad, not committed to the repo. Screenshots saved to `reports/screenshots/2026-07-03_dash-{populated,empty}.png`.
